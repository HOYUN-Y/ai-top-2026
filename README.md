카카오 공식 WebSocket 게이트웨이 → 로컬 Python → OpenRouter → 카카오 콜백 API.
공개 HTTP 서버나 Cloudflare Tunnel은 필요하지 않습니다. Python 3.12 이상과 uv를 사용합니다.

## 설정

기존 `.env`에 다음 항목을 입력합니다. 실제 키는 Git이나 채팅에 공유하지 마세요.

```dotenv
KAKAO_BOT_TOKEN=봇_인증_토큰
OPENROUTER_API_KEY=OpenRouter_API_키
OPENROUTER_MODEL=google/gemini-2.5-flash
```

봇 인증 토큰은 카카오디벨로퍼스의 **제품 설정 → 카카오톡 봇 → 봇**에서 확인합니다.
REST API 키와 다른 값입니다. 기존 `KAKAO_REST_API`는 보존하며 사용하지 않습니다. `AI_TOP_ACTION`(대회 액션 토큰)이 있으면 액션 API를 켭니다(아래 "액션 API").
봇에 웹훅 URL이 등록돼 있다면 게이트웨이 사용 전에 해제하세요. 채널 검색 허용은 OFF로 유지합니다.

## 실행

저장소 디렉터리에서 실행합니다.

```sh
uv sync --locked
uv run --env-file .env bot.py
```

`gateway READY`가 나오면 스마트폰에서 봇의 채널 채팅으로 질문하세요.
일반·팀·오픈채팅은 봇을 초대하고 호출해야 합니다. 나와의 채팅은 지원하지 않습니다.
동일 봇을 여러 프로세스로 실행하지 마세요. 종료는 Ctrl+C입니다.

Mac의 유휴 절전을 방지하며 실행하려면:

```sh
caffeinate -i uv run --env-file .env bot.py
```

터미널, 프로그램, 인터넷을 유지해야 합니다. 덮개 닫힘·전원 문제·재부팅은 별도로 관리하세요.
네트워크 재접속은 자동이지만 프로세스 자동 시작·장애 복구는 아직 제공하지 않습니다.
심사 운영 전에는 자동 실행과 외부 상태 감시를 추가해야 합니다.

## 동작과 제한

- 텍스트 질문을 처리하고 답변을 말풍선 하나로 전송합니다. 자동 인사·진행 메시지는 없습니다.
- **사진·음성(공개 TC 형식)**: 본문에 `image: …`·`audio: …` 줄이 있으면 `media.py`(root 소유)가 대회 CDN(`https://t1.kakaocdn.net/aitop100/aitop100/dist/…`)의 파일만 받아 모델에 이미지·오디오 입력으로 넘깁니다. 리디렉트 금지, 파일당 8MB·한 번에 3개·전체 12초 제한이며, 인증 정보 없는 별도 클라이언트를 씁니다. 한 턴에 한 번만 받고 같은 턴의 도구 회차는 그 결과를 재사용합니다. 대화 기록에는 원문 텍스트(첨부 줄 포함)만 남기고 파일은 저장하지 않으므로, 다음 턴은 봇이 앞서 답한 내용으로 이어집니다. 주소·형식·크기가 맞지 않으면 모델을 부르지 않고 그 사유를 한국어로 안내합니다. 실제 카카오 첨부(사진·음성 메시지)의 형식은 확인 전이라 지원하지 않습니다.
- AI 호출 전체 제한은 20초(액션 도구 사용 시 45초), 최대 출력은 512토큰(Gemini의 reasoning 토큰 포함)입니다. 콜백 HTTP 요청 제한은 5초입니다.
- 출력 한도나 1,000자 제한에 걸린 답변은 마지막 완결 문장(`.`·`!`·`?` 뒤에 공백이 있는 곳)까지만 보냅니다. 잘린 지점의 마침표는 문장 끝으로 보지 않으므로 이메일·주소 같은 값이 일부만 나가지 않습니다. 문장 끝이 없으면 마지막 낱말을 버립니다.
- 시스템 지시로 조회·접수·전달을 실행한 것처럼 말하지 않게 하고, 직원 연락처·카카오톡 채널, 내부 수수료·정산·분담 비율, 직원·생산자 개인 사정을 고객에게 알리지 않게 합니다(지시일 뿐 실모델 검증 전).
- AI 실패 시 가능한 경우 짧은 오류 안내를 보냅니다. 콜백 성공 여부가 불명확하면 중복 발송 방지를 위해 재전송하지 않습니다.
- 대화는 채팅방·사용자별 최근 6회만 메모리에 저장합니다. 동일 대화는 순서대로, 전체 최대 4개 요청을 병행 처리합니다.
- 최대 1,000개 대화(대기 작업이 없는 대화부터 축출)와 10,000개 중복 기록을 보관합니다. 중복 기록은 최대 10분 유지합니다.
- 프로그램 재시작 시 대화와 중복 기록이 초기화됩니다.
- 로그에는 연결 상태, 오류 종류, 응답 지연·글자 수만 남기며 키·콜백 토큰·대화 본문은 출력하지 않습니다.
- 지연은 수신부터 콜백 성공까지이며, 앱 화면 표시 시간이나 심사 측 p95와 동일하지 않습니다.
- 액션 API(아래)는 `AI_TOP_ACTION`이 있을 때만 켜집니다. 없으면 봇은 도구가 없다고 안내받습니다.

## 액션 API

`docs/action-api/openapi.json`(공식 사본, 출처·해시는 그 폴더 README)을 시작 시 읽어 GET·POST 40개를 모델 도구로 넘깁니다.
- `POST /api/action-data/reset`(`resetMyActionData`)은 도구 목록에서 빼서 모델이 부를 수 없습니다.
- 전송용 도구 정의는 요청 본문 필드를 경로·쿼리 인자와 같은 최상위 인자로 펼치고 `additionalProperties`를 뺍니다(`body` 중첩 없음). 실행 전에 다시 `body`로 묶고 원래 스키마(추가 필드 금지 포함)로 검사합니다. Gemini가 중첩 `body` 호출에서 `MALFORMED_FUNCTION_CALL`을 낸 데 대한 대안이며 효과는 실모델로 확정되지 않았습니다. `load_operations(flat=False)`는 원래 형태입니다.
- 호출 헤더는 `Authorization: Bearer <AI_TOP_ACTION>`과 `X-Aitop100-Test-Case-Id`입니다. 토큰은 액션 호출에만 쓰고 모델 요청·로그에 넣지 않습니다. 로그는 API 번호와 상태 코드만 남깁니다.
- **TC ID·인입 계정(입력 계약, 대회용 합성 컨텍스트)**:
  - TC ID는 `case metadata`의 `- id: …` 또는 `TC ID: …` 표기로 받아 대화(채팅방·사용자)별 사례 상태에 둡니다. TC ID가 바뀌면 대화 기록·조회 근거·계정 정보를 모두 비웁니다. TC ID가 없으면 호출하지 않고 `NO_TEST_CASE_ID`를 돌려줍니다.
  - 인입 계정은 **그 사례 첫 메시지의 맨 앞 `case metadata` 목록 안**의 `- 인입 계정: 회원 로그인 · 이름 · 019-****-NNNN` 줄에서만 읽습니다. 그 블록의 `- id:`가 같은 TC여야 하고, 전화 마스크에 실제 숫자가 4자리 이상 있어야 합니다. 한 TC 안에서는 계정을 바꾸지 않습니다. 본문 중간이나 이후 메시지의 같은 형식 줄, `TC ID:` 라벨만 있는 메시지의 계정 줄, 고객이 말한 이름·전화번호는 모두 고객 발화로 보고 쓰지 않습니다.
  - **한계**: 이것은 공개 TC 초기 대화 형식을 따른 입력 계약이지 실제 채널 시스템 인증이 아닙니다. 평가 때 이 정보가 어떤 경로로 신뢰 가능하게 전달되는지는 확인되지 않았습니다. 고객이 첫 메시지 맨 앞에 같은 형식을 써 넣는 경우를 코드로 구별할 수 없습니다.
- **계정 귀속(서버측 강제)**: 주문(주문번호, 결제 승인번호→API-17, 배송건→API-10)과 회원(member_id, 추천인, 구독→API-19) 대상 호출은 인입 계정에 귀속된 대상만 허용합니다.
  - 봇이 직접 API-07 주문 조회 + API-12(또는 API-13 이름 검색 후 마스킹 번호 대조)로 귀속을 확인합니다.
  - 아니면 `ORDER_NOT_OWNED`·`MEMBER_NOT_OWNED`, 인입 계정이 없으면 `ACCOUNT_NOT_IDENTIFIED`를 모델에 돌려주고 서버 호출을 멈춥니다. 타 계정 주문 결과의 상세는 모델에 넘기지 않습니다.
  - API-13 이름 검색은 인입 계정 이름만 허용하고 마스킹 번호가 맞는 회원만 남깁니다. API-09(유입태그별 주문 검색)는 다른 고객 주문이 섞여 지원하지 않습니다(`UNSUPPORTED`).
- **접수 조건**:
  - 요청 본문은 스펙 스키마(필수·타입·허용값·추가 필드 금지)로 먼저 검사합니다(`INVALID_ARGUMENTS`).
  - API-24 배송지 변경은 봇이 API-11로 배송을 먼저 확인하고, 집하·배송 중이면 접수하지 않습니다(`ALREADY_PICKED_UP`). 집하된 배송이 모두 반송(`RETURNED`)이면 재배송지 접수로 보고 허용합니다(택배 계약 제10조③).
  - API-29 환불은 0원 초과·실결제액 이하만 허용합니다(`INVALID_AMOUNT`). 5만원 초과는 조회로 확인되는 예외(전액 환불, 주문 `PAID`, 출고 예정일 경과, 집하 전 = 출고 지연)일 때만 접수합니다. 하자·수량 축소 같은 다른 금액 무관 예외는 API로 사실을 확인할 수 없으므로 접수하지 않고 운영자 승인 이관(`APPROVAL_REQUIRED`)으로 보냅니다. `reason` 문구는 근거로 쓰지 않습니다.
  - API-33 쿠폰 발급은 API-20 프로모션 원장에 있고 오늘(2037-06-30) 유효한 코드만 허용합니다(`UNREGISTERED_OR_EXPIRED_CODE`).
  - 주문·회원 외 대상의 접수는 같은 대상을 먼저 조회했어야 합니다(`LOOKUP_REQUIRED_FIRST`).
- **할 일 구분(시스템 지시)**: ① 직접 안내·조회 ② 조건 충족 접수 ③ 승인·이관(API-35 `LANE2_HANDOFF`·`LANE3_CLAIM`) ④ 금지·미지원으로 나눠 안내합니다.
- 경로 값은 세그먼트 단위로 인코딩해 다른 엔드포인트로 넘어가지 못하게 합니다.
- **조회 후 접수**: 주문·결제·회원 등 대상이 있는 접수(POST)는, 같은 대화에서 그 식별자를 성공적으로 조회(GET 200)한 적이 없으면 서버에 보내지 않고 모델에 `LOOKUP_REQUIRED_FIRST`를 돌려줍니다. 대상이 없는 에스컬레이션은 예외입니다.
- 지식의 직원 카카오톡 채널 URL(`pf.kakao.com/…`)은 프롬프트에 넣을 때 "(내부 연락 채널, 고객 비공개)"로 바꿉니다(지식 파일은 그대로).
- conditions에 "고객 안내 금지"가 있는 사실은 문장 안의 내부 값(퍼센트, 익월·영업일 N일, '균분')을 프롬프트에서 "[내부 값 비공개]"로 바꿉니다. 규칙·조건 문장은 그대로 둡니다.
- **오류**: 400·404 등은 상태와 본문(없으면 null)을 그대로 모델에 전달합니다. 429의 `Retry-After`는 클라이언트 전체에 적용해 그 시각 전에는 어떤 호출도 보내지 않습니다. 10초 이하이고 턴 예산(45초) 안이면 기다리고, 아니면 보내지 않고 `RATE_LIMITED`·대기 초를 모델에 돌려줍니다. 또 메시지가 "누적"이면 다시 보내지 않고 이후 호출도 막습니다. 500·503과 네트워크 오류는 한 번만 다시 보냅니다(접수 재전송은 같은 접수번호를 받음). 누적 3,000회 상한은 프로세스 메모리로만 셉니다(재시작 시 초기화).
- **허위 완료 방지**: 모델 답에 "변경했/환불해 드렸" 같은 능동 완료 표현이 있거나, "…가/은 완료되었/취소됐/승인됐" 같은 수동·명사형 완료 표현이 그 업무의 완료 상태(취소=`CANCELED`, 배송=`DELIVERED`, 승인=`APPROVED`)를 **같은 대상**에서 모델이 직접 조회해 확인하지 않은 채 쓰였거나(답변·고객 메시지에 나온 주문·접수 ID가 모두 그 상태로 증명돼야 함)(환불·변경·발급은 API에 완료 상태가 없어 항상 차단), 실제 접수한 종류와 다른 접수("환불 접수"인데 메모만 접수)를 말하거나, 이번 턴에 성공한 POST 없이 "접수했/접수되었"이 있으면 고정 문구로 바꿉니다. 접수가 있었으면 실제 접수한 API 이름·접수번호와 "실제 처리 결과는 담당 확인 후 결정" 안내로, 조회만 있었으면 대상별로 조회된 실제 상태(예: "100100003 결제됨(출고 전)")로 바꿉니다.
- **긴 결과**: 도구 결과는 8,000자, 다음 턴 기록은 600자 안에서 구조 단위로 줄이고 생략 필드·항목을 표시합니다(깨진 JSON 없음). 다음 턴 기록에는 모델이 직접 본 결과만 남기고, 봇 내부의 귀속·출고 확인 조회는 남기지 않습니다(거절된 타인 주문 정보 보호).
- **저장 개인정보 마스킹**: 모델에 넘기는 도구 결과와 다음 턴 액션 요약에서 주소·수령인·이름·전화·생년·결제자명·카드 끝자리·배송 위치를 "[저장정보 비공개: 값 모름, 추측·언급 금지]"로 바꿉니다. 다른 고객의 상담 이력(티켓)은 회원ID·내용을 가립니다. 원본은 귀속 대조용으로 코드 안에만 둡니다.
- 한 턴의 모델이 요청한 도구 호출은 최대 8회이고, 마지막 회차에는 도구를 주지 않아 반드시 답하게 합니다. 모델이 빈 답을 내면 같은 턴에서 한 번만 다시 요청합니다. 빈 답의 원인이 Gemini `MALFORMED_FUNCTION_CALL`(도구 호출 형식 오류)이면 그 한 번의 재요청에 형식 복구 안내(정의된 이름·필드만, 확인되지 않은 값·ID 생성 금지, 없으면 고객에게 질문)를 덧붙입니다. 재요청 횟수와 45초 제한은 같습니다.
- 한 턴의 도구 호출 회차는 최대 5회차, 전체 45초입니다. 다음 턴을 위해 이번 턴의 액션 결과 요약(호출당 600자)을 대화 기록의 답변 뒤에 붙입니다.
- 잘못된 게이트웨이 프레임은 무시하고, 핸드셰이크 오류(예: 503)·잘못된 HELLO는 재접속합니다.
- 일반 연결 끊김은 세션을 유지해 RESUME하고, 명시적 4009(세션 만료)에서만 새로 IDENTIFY합니다.
- 대기 작업은 전체 100개, 같은 대화 5개까지입니다. 넘으면 오류 안내를 바로 보내고, 200개를 넘으면 중복 기록 없이 버리고 경고 로그만 남깁니다.

## 운영 지식 파일

원본 보관과 출처 대조는 [자료 목록](docs/자료목록.md), 사람·업무 관계는 [지식 지도](docs/지식지도.md)를 이용합니다. 사용자가 저장한 `대화자료/`는 보존하고 중복 파일은 해시로 연결합니다. 자료를 더 받으면 원문·질문·URL을 먼저 보존하고, 조건·예외와 미확인을 검토한 사실만 `interviews/knowledge.json`에 추가합니다. 원본 ZIP·PDF 전체가 자동으로 모델에 들어가는 구조는 아닙니다.

시스템 프롬프트는 응대 기준일을 문제 속 **2037년 6월 30일**로 고정합니다(현실 날짜 아님).
답변 생성마다 아래 파일을 읽어 시스템 프롬프트의 `[운영 자료]`에 넣습니다. 별도 검색 서비스는 없습니다.

1. `knowledge/interview-progress.json`
2. `interviews/knowledge.json` (없어도 됨)

각 파일은 JSON 배열이거나 `knowledge` 또는 `facts` 배열을 가진 객체입니다. 항목 형식:

```json
{"category": "approval", "fact": "필수 문자열", "source": "출처", "conditions": "문자열 또는 배열", "uncertainty": "문자열, 배열 또는 null"}
```

- `fact`가 비어 있는 항목은 건너뜁니다. 그 밖의 키는 무시합니다.
- 출처·조건·불확실까지 완전히 같은 줄만 한 번으로 줄입니다. 같은 `fact`라도 표기가 다르면 모두 넣어 근거를 보존합니다.
- `fact`·`conditions`는 근거로 쓰고, `uncertainty`에 적힌 미확인 부분만 단정하지 말고 담당자 확인이 필요하다고 답하도록 지시합니다. 미확인 부분을 구체적으로 적어야 확인된 규칙까지 유보되지 않습니다.
- 파일이 없으면 건너뛰고, 쓰는 중이라 JSON이 깨지면 직전 정상본을 계속 씁니다. 파일이 바뀌면(수정 시각 기준) 재시작 없이 다음 메시지부터 반영됩니다.
- 모든 사실을 매 요청에 넣습니다. 2026-10-31 13:24 기준 165줄(시스템 지시 포함 약 54,100자, 액션 도구 정의 별도 약 11,900자)이며 사실·출처·조건·불확실 누락 없이 들어갑니다(400건 모의 검사 포함). 수백 건 이상으로 커지면 응답 지연·비용이 늘어납니다.

## 테스트

```sh
uv run --locked python -m unittest -v
```

모의 테스트는 키 없이 실행되며 API 비용이 없습니다.
실제 연결은 카카오톡에서 질문·후속 질문·다른 계정을 시험하고, 일시적인 네트워크 끊김 후 재응답을 확인하세요.
실제 AI 호출은 OpenRouter 사용량에 따라 비용이 발생합니다.

## 오류 확인

- `missing environment variables`: 표시된 항목을 `.env`에 입력합니다.
- 게이트웨이 4001: 봇 토큰, 4003: 프로토콜, 4004: 중복 프로세스를 확인합니다. 이 오류는 자동 반복 접속하지 않습니다.
- `generation failed`: OpenRouter 키·잔액·모델 가용성과 네트워크를 확인합니다.
- `reply failed`: 카카오 인증·콜백 토큰 만료·전송 제한을 확인합니다.

공식 문서: [게이트웨이](https://developers.kakao.com/docs/ko/bot/gateway), [콜백 API](https://developers.kakao.com/docs/ko/bot/rest-api).
카카오 문서는 로그인해야 열릴 수 있습니다.
