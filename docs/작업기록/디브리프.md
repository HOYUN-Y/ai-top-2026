# 디브리프 담당 작업기록

작성일: 2026-10-31, 대회 종료 후. 시각은 KST 기준이다. 이 기록은 디브리프 전용 포크에서 수행한 문서 작업과 전달받은 사실을 구분해 남긴다.

## 1. 맡은 목적과 범위

대회 문항인 “제출한 AI 에이전트의 강점, 특히 어떤 상황을 잘 처리하도록 설계했는지와 그 이유”에 답하는 문안을 작성했다. 사용자가 제공한 다섯 가이드인 강점·정보 획득 접근·검증 방식·주요 설계와 구현·아쉬움과 한계를 따랐다. 짧은 요약과 본문, 제출에서 제외할 편집 근거를 분리하고, 최종 보고가 들어올 때마다 확인된 범위만 갱신하는 것이 역할이었다.

감독 세션을 포크하면서 대회 준비, 인터뷰, 구현, 검수의 대화 맥락을 물려받았다. 포크 이전의 채널 연결·인터뷰·지식 수집·코드 작성은 이 세션의 신규 작업이 아니다. 디브리프 역할을 받은 뒤에는 다른 세션·페인, 카카오톡·Chrome, 코드·지식 파일·서버를 조작하지 않았다. 처음에는 초안만 작성했고, 이후 사용자가 제출본 생성과 문체 편집용 모델 호출을 별도로 허용했다.

기능 목록을 길게 나열하기보다 고객 상황에서 설계 이유로 이어지도록 편집했다. 냉동 수산물의 운송 중 온도 이탈, 과거 홍보물과 개정 규정의 충돌, 타인의 주문 정보 요청, 환불 접수와 실제 처리 완료의 차이를 중심 사례로 삼았다. 지식 지도와 인터뷰 경로의 가치는 “누가 사실을 아는가”와 “누가 결정할 권한이 있는가”를 구분하는 과정으로 설명했다.

### 문체 편집용 Gemini 호출의 실제 경위

사용자가 기존 OpenRouter 키로 Gemini 문체 편집을 직접 실행하도록 요청했다. `uv --env-file`로 환경에만 키를 로드했으며 `.env` 본문이나 키 값을 출력·문서화하지 않았다. 전송 대상으로는 초안의 제출 문항·가이드·본문과 확인된 대회 사실을 추렸고, 실제 고객 대화와 편집용 메모는 제외했다.

첫 시도는 `URLError`로 결과를 얻지 못했다. 권한 재시도는 자동 승인 검토가 이번 문서 전송의 권한을 확인하지 못해 거절했다. 이를 알리고 명시적 재승인을 받은 뒤 `google/gemini-2.5-flash` 호출 두 건이 완료됐다. 두 후보는 각각 5,296자와 5,372자, 종료 사유 `stop`이었으며 임시 파일에 보관했다. 첫 결과가 원문을 거의 반복해 두 번째에 압축 편집을 요청했다. 이 후보들을 제출본에 그대로 반영하지는 않았다.

이후 감독 세션이 추가 호출 중단과 별도 후보 전달을 지시해 즉시 중단했다. 최종 문체 반영에는 감독 세션이 만든 [Gemini 후보](../../coordination/debrief-gemini-candidate.md)와 [호출 기록](../../coordination/debrief-gemini-wash.json)을 사용했다. 이 후보의 3,858자·8,886ms 결과는 감독 세션의 호출이며, 이 세션의 호출 성과나 챗봇 응답 성능으로 기록하지 않았다. 후보를 기존 문안·최신 사실과 대조한 후 자연스러운 표현만 선택해 반영했다.

## 3. 주요 판단과 문서 검증

**확인 시점과 완료 범위를 보존했다.** 초기 8명·64문답·26원본·238+11지식을 최종 집계처럼 고정하지 않았다. R8 완료 때에는 68문답으로 갱신하되 신규 ZIP 세 개가 검수 중인 동안 자료·지식 수에 합산하지 않았다. 독립 검수와 병합 완료 전달 후 29원본·255+11지식으로, 최종 인터뷰 보고 후 9명·72문답으로 바꿨다. 원본 29개는 intake 28 URL 자료와 초기 B10 위임표 1개이며 중복 0이라는 감독 보고를 반영했다. 원본 중복을 이 세션이 새로 검사한 것은 아니다.

**Gemini 문장을 사실의 근거로 쓰지 않았다.** 감독 후보에는 이전의 68문답·26원본·238지식, 신규 자료 검수 중 상태, S9 실패만 남아 있었다. 문체는 참고하되 집계와 검수 상태는 최신 보고에 맞췄다. 반대로 실패 기록을 모두 지우지도 않았다. 재시도만으로 형식 오류가 해결되지 않았던 과정과 평면 도구 구조의 제한된 성공, 남은 안내 누락을 함께 기록했다.

**직접 한 검증은 문서 대조였다.** 관련 보고를 읽고 본문을 재독했으며, 간단한 로컬 문자열 점검으로 가이드 다섯 항목, 필수 수치·한계, 오래된 “대기·미검증” 표현, 요약·본문 글자 수를 확인했다. 한 번은 과거 Gemini 후보의 상태를 설명하는 편집 기록의 “검수 중”까지 오래된 본문으로 잡았고, 본문과 이력 설명을 분리해 다시 확인했다. 이는 문서 확인이며 봇 코드·모델·액션의 신규 성능 검사가 아니다.

## 5. 미완료·한계와 다음에 참고할 사항

이 세션은 제출용 문안까지 만들었으며 실제 대회 제출 여부나 최종 입력 분량을 확인하지 않았다. 제출본의 상단 편집 메모와 마지막 확인 기록은 제출에서 제외하도록 표시했다. 기존 초안에는 당시 수치가 남아 있으므로 최신 성과를 인용할 때는 제출본과 개별 근거 보고를 우선해야 한다. 이후 결과를 추가할 때도 시험 환경, 지정 코드, 표본 수, 실서버와 모의 실행을 함께 확인해야 한다.

문안에 남긴 한계는 관계자 한 명 미인터뷰, 실제 업무 POST·전체 정확도·평균 및 p95·장기 운영 미검증, 접수 이후 안내 누락, 원문에 없는 조건 추가다. 자동 재시작을 확인했어도 메모리 대화·중복 기록은 재시작 시 초기화되고, 덮개·전원·인터넷·로그인 유지에 의존한다. 검색 CLI의 0.1~0.4ms는 자료 검색 시간이며 챗봇 응답 속도가 아니다.

종료 후 사용자가 전달한 최종 운영 인계 사항은 다음과 같다. 이는 이번 작업기록 작성 중 새로 조회·검증한 상태가 아니다.

- 제출봇 **멍멍이**, App ID **702917**.
- 로컬 LaunchAgent `gui/501/local.ai-top-2026.bot`, 실행 폴더 `/Users/lyuhoyun/.local/share/ai-top-2026`.
- OpenRouter의 `google/gemini-2.5-flash` 사용. Vercel은 최종 운영에 채택하지 않았다.
- 지식 **266건(255+11)** 전체를 프롬프트에 제공한다. 검색 CLI는 내부 자료 탐색용이며 런타임 검색에는 연결하지 않았다.
- 구체적인 운영 유지·이전 절차는 [로컬 운영 문서](../로컬-운영.md)를 참고한다. 이 기록을 남기면서 재배포나 서비스 재시작은 하지 않았다.

이번 종료 작업은 이 파일 작성과 저장 확인으로 끝낸다. 비밀 키 값은 기록하지 않았고, 원본·코드·지식·제출물·설정·현재 서버를 수정하거나 API·카카오톡·Chrome을 조작하지 않았다. 페인 종료와 최종 정리는 감독이 맡으며, 이 세션은 스스로 페인을 닫거나 git commit/push하지 않는다.
