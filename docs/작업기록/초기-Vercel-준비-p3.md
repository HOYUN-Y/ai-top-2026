- **작성:** 2026-10-31 대회 종료 후, p3 세션이 직접 작성했다.
- **기록 근거:** 이 세션의 대화 기록과 아래 산출물이다. 이 세션의 작업은 모두 이 세션이 직접 했다. 포크로 물려받은 작업은 없다.
- **이번 작성에서 하지 않은 것:** 새 검증, 재배포, 코드·설정·`.env` 수정, 카카오톡·Chrome 조작, API 호출.

## 1. 맡은 목적

- **연결 경로 확인.** 처음 질문은 "카카오톡 봇을 연결하려면"이었다. 이어서 대회 준비 공지를 받고, 제출봇을 카카오톡 채널 챗봇으로 연결하는 경로를 확인했다.
- **현재 상태 진단.** 사용자가 "챗봇beta에서 내 봇이 안 보인다"고 해서, 봇·채널이 어떤 상태인지 확인했다.
- **서버 초안 배포.** 사용자가 Vercel 웹훅과 OpenRouter를 고른 뒤, 최소 에이전트 서버를 만들어 배포했다. 웹훅 수신, 즉시 204 응답, LLM 답변, 카카오 콜백 답장까지 넣었다.

**공식 문서**
- 콘솔의 "문서 확인" 링크 `/docs/in/bot/prerequisite`는 세 번 열어 봤지만 모두 "일시적인 오류"였다.
- 문서 홈에서 실제 경로를 찾았다: `/docs/ko/bot/{common,tutorial,prerequisite,rest-api,gateway,webhook,trouble-shooting}`
- 웹훅 문서(`/docs/ko/bot/webhook`)를 읽고 다음 규격을 확인했다.
  - 카카오가 등록된 URL로 `POST {op, t, d}`를 보낸다. 메시지 이벤트는 `t="MESSAGE_CREATE"`이고, `d`에 `content`, `botUserKey`, `callbackToken` 등이 들어 있다.
  - 봇 서버는 **1초 안에 2xx**(본문 없이 204)로 응답해야 한다.
  - 답장은 `POST https://kapi.kakao.com/v1/bot/callback`으로 보낸다.
    - 헤더: `Authorization: KakaoAK {봇 인증 토큰}`, `X-Bot-Callback-Token`
    - 본문: `skillResponse`(version 2.0, `simpleText`)
    - 콜백 토큰이 **5분** 안에 만료되기 전에 보내야 한다.
  - 웹훅 등록 시 커스텀 헤더를 넣어 출처를 검증할 수 있다.

## 3. 주요 판단 이유

- **콜백 방식.** 문서상 웹훅은 1초 안에 응답해야 하고 답장은 콜백으로 따로 보낸다. 그래서 "204 먼저, 처리는 뒤에서" 구조를 택했다. Vercel에서는 응답 뒤 작업이 끊기지 않도록 `@vercel/functions`의 `waitUntil`을 썼고, 콜백 토큰 만료(5분)에 맞춰 `maxDuration`을 300초로 잡았다.
- **Vercel 추천.** 심사가 끝날 때까지 무중단 응답이 필요해서, 노트북 상태와 상관없는 Vercel을 추천했다. 사용자가 이를 골랐다. **최종 운영에서는 채택되지 않았다**(4절 참고).
- **OpenRouter.** 사용자가 지정했다. OpenAI 호환 `chat/completions`의 `tools`를 그대로 쓸 수 있어서 별도 SDK 없이 `fetch`만 썼다.
- **대화 기록 보관.** 대화 기록은 사용자 질문과 최종 답변만 남기고 최근 20개로 자른다. 도구 호출 중간 메시지가 잘린 채 남아 다음 요청이 깨지는 것을 막기 위해서다.
- **비밀 값 처리.** 키는 사용자가 별도 터미널에서 `vercel env add`로 직접 넣도록 안내했다. 채팅과 대화 기록에 키 값이 남지 않게 하려는 것이다.

## 6. 미완료·한계

- **환경변수 미설정.** 이 세션은 Vercel에 `BOT_TOKEN`, `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`을 넣지 않았다. 사용자가 넣었는지는 확인하지 못했다.
- **웹훅 미등록.** 이 세션은 카카오 콘솔에 웹훅 URL을 등록하지 않았다. 나중에 다른 세션이 어떤 URL을 등록했는지는 모른다.
- **액션 API 미연동.** 주문 조회, 환불 요청, 담당자 이관 등은 명세를 받기 전이어서 연결하지 못했다.
- **보안 헤더 꺼짐.** 커스텀 헤더 검증은 기본으로 꺼져 있다. 환경변수가 없으면 출처를 검증하지 않는다.
- **대화 기록 휘발.** 대화 기록은 인스턴스 메모리라서, 콜드 스타트나 인스턴스가 바뀌면 맥락이 사라진다.
- **1000자 절단 근거.** `simpleText` 1000자 제한은 과거 오픈빌더 기준으로 넣었다. 새 카카오톡 봇 API 문서에서는 확인하지 않았다.
- **배포 잔존.** Vercel 배포는 그대로 남아 있다. 환경변수가 없는 상태라면 이 주소로 온 메시지에는 답장이 실패한다.
- **이 세션의 잘못된 안내 (정정했음)**
  - 처음에 오픈빌더 스킬 방식(즉시 응답 JSON, 5초 제한)을 설명했는데, 대회의 "카카오톡 봇" 상품과 달랐다.
  - 챗봇 메뉴의 "발견 탭"을 근거 없이 안내했다. 출처는 ChatGPT 챗봇 재추가 블로그였다.
  - 두 가지 모두 대화 중에 정정했다.

## 7. 다음에 참고할 사항

- **봇 테스트 방법.** 채널 검색 허용이 꺼져 있으면 카카오톡 검색에 안 나온다. 1:1 테스트는 채팅 URL `http://pf.kakao.com/_xmaNWX/chat`로 들어간다. 단톡방의 "챗봇beta" 목록은 별도의 "그룹채팅 챗봇 beta 입점 신청" 대상으로 보인다. 화면 문구만 보고 추정했고 확인하지는 않았다.
- **공식 문서 경로.** 콘솔 링크(`/docs/in/...`)는 깨져 있었다. 실제 문서는 `https://developers.kakao.com/docs/ko/bot/webhook`, `.../gateway`, `.../rest-api`다.
- **웹훅 규칙.** 1초 안에 2xx로 응답하고, 5분 안에 콜백을 보낸다. 웹훅과 게이트웨이는 하나만 쓸 수 있다. 서버리스에서는 응답 뒤 작업을 이어갈 장치(`waitUntil` 등)가 반드시 필요하다.
- **Vercel 정리.** Vercel 프로젝트 `kakao-agent`는 최종 운영에 쓰이지 않는다. 카카오 웹훅이 이 주소를 가리키고 있지 않은지 확인하고, 필요 없으면 정리한다. 정리 여부는 사용자가 판단한다.
