## 1. 맡은 목적

- **사람 지도.** 「교동마을 산지직송」 CS 에이전트용으로, 인터뷰 대상자마다 "무엇을 아는지(사실)"와 "무엇을 정하는지(권한)"를 나누고 근거를 단다. 누가 누구를 소개했는지(연락처 획득 경로)도 그린다.
- **자료 판독.** 새로 들어온 첨부 자료를 안전하게 받아 정적으로 판독하고, runtime 지식 **후보**를 만든다. 최종 병합은 root 몫이다.
- **질문 후보.** 남은 인터뷰 대상과 업무 공백을 찾는 업무 질문 후보를 쓴다. 승인·발송 권한은 없었다.
- **세컨드브레인.** 마감 직전에 인계받은 검색 도구를 검증하고, 사용 문서와 봇용 공통 지식 후보를 만든다.

## 3. 주요 판단과 이유

- **"아는 사람"과 "정하는 사람"을 분리했다.** 같은 사건이라도 현장 사실(온도·배송)과 정책 판단(환불·예외)을 묻는 대상이 다르다. 권한은 위임표·계약서·조직 관계도 문구로만 적었다.
- **이름과 관계를 지어내지 않았다.** 이름만 지목된 사람(박민아, 홍보걸, 생산자 3명)은 채널과 응답이 확인되기 전까지 확보 인원에 세지 않았다. 열 번째 사람은 끝까지 특정하지 않았다.
- **"모름"을 "없음"으로 바꾸지 않았다.** 담당자를 모른다는 답이 담당자가 없다는 뜻은 아니므로, 미확인으로 남기고 다음 경로를 적었다.
- **원문끼리 충돌하면 결론을 내지 않았다.** 대표 사례:
  - 부분환불 R<30% 구간의 재배송 제시 여부(판매·환불 규정 제19조②)
  - 임계표가 현행판인지
  - 6/24 경고음의 발생원
  - 카탈로그의 12종/13종, 33건/34행 표기
- 이런 항목은 그대로 기록하고 판단을 root에 넘겼다.
- **API는 권한이 아니다.** 접수 API의 성공은 처리 완료가 아니라는 README 문구를 업무범위표 전체의 전제로 삼았다.
- **같은 질문을 반복하지 않았다.** 이미 "모름" 순환으로 닫힌 경로는 재질문 후보에서 뺐다. 실제 기록 문서가 언급된 연결만 추천했다. 예: 박민아의 날짜별 메모, 고길동이 가진 개정 이력.

## 5. 다른 세션에서 전달받은 사실 (내 작업 아님)

- **root:** 후보를 대조해 runtime에 병합했다. 최종 숫자는 구조화 지식 **266건(runtime 255 + 초기 11)**, 원본 29개, 직접 응답 9명, 감독 문답 72건이다. 검색 도구 원본 작성과 R7·R8 질문 승인도 root가 했다.
- **interview 세션:** 카카오 채널 질문 발송과 원문 수집(`interviews/sources/round*-transcript.json`).
- **implement 세션:** 일부 초기 ZIP 판독과 전역 `research/source-manifest.json`·자료목록 관리.
- **최종 운영 상태(감독 전달, 이 세션은 확인하지 않음):**
  - 제출 봇 App ID 702917은 로컬 LaunchAgent로 유지된다. 모델은 OpenRouter `google/gemini-2.5-flash`다.
  - Vercel은 최종 운영에 채택하지 않았다.
  - 지식 266건은 전체 프롬프트로 사용한다.
  - 검색 CLI는 내부용이며 런타임에 연동되지 않았다.

## 7. 다음에 참고할 사항

- 새 자료는 다음 순서로 다룬다: 전용 폴더에 저장 → manifest(URL·해시·제공 질문) → 정적 판독 → notes(원문 요지·대조·미확인) → facts-candidate(조건·미확인 포함) → root 병합.
- zsh에서는 `set -- $var`로 단어가 분리되지 않는다. 다운로드 루프는 함수 인자로 넘긴다(이번에 빈 경로가 생겨 즉시 삭제한 적이 있다).
- 날짜를 정해서 묻는 질문(예: 특정 로트·출고일)이 "모름" 순환을 끊는 데 효과적이었다. 사람에게는 문서 위치를 묻고, 내용은 문서에서 읽는다.
- 검색 질의는 원문 용어로 바꿔 넣는다. 예: 다른 사람 → 타인·타 계정, 녹았다 → 해동·이탈·온도.
