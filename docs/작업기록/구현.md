# 작업 기록 — 구현 담당

작성: 2026-10-31(대회 종료 후). 이 문서만 새로 썼다. 코드·지식·설정·실행 서버는 건드리지 않았다. 비밀 키 값은 적지 않는다.

## 1. 맡은 목적

교동마을 산지직송 고객상담 카카오톡 봇(`bot.py`)을 구현했다. 원 지시는 [`coordination/implementation-brief.md`](../../coordination/implementation-brief.md)이고, 범위는 다음과 같다.

- 게이트웨이 봇에 최소 지식을 연결하고 안정성 결함을 수정한다.
- 그 뒤 공식 액션 API 스펙으로 도구 호출을 연동한다. 계정 귀속·개인정보·환불 위임 한도·허위 완료 방지를 서버 측에서 강제하는 것이 목표다.
- 모의 회귀 테스트를 만든다.
- 소유 파일은 `bot.py`, `test_bot.py`, README의 실행·한계 절, `coordination/implementation.md`다. `media.py`·`test_media.py`는 root 소유다.

중간 한 시기에는 자료 판독 담당을 겸했다(§2.4).

- 두 지식 파일([`knowledge/interview-progress.json`](../../knowledge/interview-progress.json), [`interviews/knowledge.json`](../../interviews/knowledge.json))을 출처·조건·불확실성과 함께 시스템 프롬프트에 넣는다.
  - 중복 제거는 완전히 같은 줄만 한다.
  - `items`가 목록이 아니면 직전 정상본을 유지한다.
  - "고객 안내 금지" 조건의 내부 수치와 직원 채널 URL은 마스킹한다.
- 산출물: [`bot.py`](../../bot.py), [`test_bot.py`](../../test_bot.py), [`README.md`](../../README.md), [`coordination/implementation.md`](../../coordination/implementation.md)(전 과정의 실행 보고)

### 2.2 액션 API 연동 ([`docs/action-api/openapi.json`](../../docs/action-api/openapi.json) 기준)
- **도구 노출:** GET/POST 40개를 도구로 노출하고, `resetMyActionData`는 숨긴다.
- **호출 헤더:** Bearer 토큰과 `X-Aitop100-Test-Case-Id`를 붙인다. TC ID는 대화별로 유지하고, 새 TC에서 이력·조회 상태를 초기화한다.
- **경로 인자:** 경로 인자는 인코딩해 다른 엔드포인트로 넘어가지 않게 했다.
- **오류·재시도:**
  - 429는 클라이언트 단위 not-before 시각과 45초 턴 예산 안에서만 기다린다. "누적" 한도이면 이후 호출을 중단한다.
  - 500/503은 1회만 재시도한다.
  - 누적 3,000회 상한은 메모리로 센다.
- **계정 귀속:** 선두 `case metadata` 블록의 인입 계정을 기준으로 한다.
  - 마스크 번호는 실숫자 4자리 이상이어야 하고, 첫 메시지에서만 받으며 교체하지 않는다.
  - 주문(API-07+12)·회원·결제·배송·구독 대상이 이 계정에 속하는지 내부 조회로 강제한다. 타인 주문이면 `ORDER_NOT_OWNED`와 LANE2_HANDOFF 안내를 돌려준다.
- **접수 조건:**
  - 배송지 변경은 집하 전에만 받는다. 예외로, 집하된 배송이 모두 반송(`RETURNED`)이면 받는다(택배 계약 제10조③).
  - 환불은 0원 초과·실결제액 이하만 받는다. 5만원 초과는 조회로 입증되는 출고 지연 전액환불만 허용하고, 나머지는 승인 이관(`APPROVAL_REQUIRED`)으로 보낸다. `reason` 문구는 근거로 쓰지 않는다.
  - 쿠폰은 API-20 원장에 등록돼 있고 오늘 유효한 코드만 받는다.
  - 위의 조건 외 대상에 대한 POST는 먼저 같은 대상을 조회해야 한다.
- **허위 완료 방지:**
  - 접수번호 없이 접수했다는 표현과, 다른 종류의 접수를 말하는 표현을 막는다.
  - 완료 표현은 **같은 레코드 객체**의 완료 상태(CANCELED/DELIVERED/APPROVED)가 있어야 통과한다. 목록·상위 객체·요청 인자를 증거로 합치지 않는다.
- **개인정보:**
  - 저장 개인정보(주소·수령인·전화 등)는 모델 입력에서 마스킹한다.
  - 다음 턴 이력에는 모델이 직접 본 결과만 남긴다. 거절된 타인 주문의 상태는 남지 않는다.
  - 긴 결과는 구조 단위로 줄이고 생략 표시를 남겨, 깨진 JSON이 생기지 않게 했다.
- **루프 상한:** 모델 도구 호출은 턴당 8회까지이고, 마지막 회차에는 도구를 주지 않는다.
- **미디어:** root의 `build_content`를 턴당 1회 호출한다. `MediaInputError`이면 한국어 안내만 보낸다.
- **도구 스키마 평면화:** 전송용 정의에서 요청 본문 필드를 최상위 인자로 펼치고 `additionalProperties`를 뺐다. 실행 전 `nest()`로 원래 `body`로 되돌리고, 원 스키마로 로컬 검증한다(§3).
- 모델 기본값은 `google/gemini-2.5-flash`이고, `max_tokens`는 512, 최종 답은 1,000자다. 잘린 답은 공백이 뒤따르는 문장부호에서만 자른다. 이메일 등 부분 값이 나가지 않게 하기 위해서다.

## 3. 주요 판단과 이유

- **출력 정규식보다 상태 근거를 택했다.** 검수 피드백에 따라 허위 완료·환불 우회를 문구 패턴이 아니라 조회 결과(상태·금액·출고 예정일·집하 여부)로 판정했다. 낱말 기반 예외는 우회가 재현돼(S3-B) 제거했다.
- **입력 계약은 인증이 아니라고 명시했다.** `case metadata`는 대회 합성 컨텍스트다. 고객 발화를 인증으로 올리지 않는다는 점을 README에 적었다.
- **증명할 수 없으면 승인 이관한다.** 하자·수량 축소 같은 고액 예외는 API로 사실을 확인할 수 없으므로 접수 대신 승인 이관으로 보냈다.
- **도구 스키마를 평면화했다.** 평면 인자 호출은 줄곧 성공했고, 실패는 중첩 `body`가 있는 API-24 단계에서만 났다. Gemini 문서의 `parameters`는 OpenAPI 부분집합이며 `additionalProperties`를 나열하지 않는다. 문서상 이름(`API-24`)은 허용 문자이므로 이름 치환은 추정 변경이라 하지 않았다.
- **TC별 정답 하드코딩은 하지 않았다.** 프롬프트 보완(식품 안전 후속, 사진·음성의 확인/미확인 구분, 빈 배송 목록 = 집하 전)은 모두 일반 규칙으로만 넣었다.

## 5. 미완료·한계

- 평면 스키마로 **L-03 실모델 접수 완결**을 확인한 것은 1표본 격리 결과뿐이다. 중첩 `body`가 원인이라는 것은 유력 가설이며, C~E 변형(단독 도구·이름 별칭)은 실행되지 않았다.
- 실제 카카오 왕복은 review 담당이었고, 결과를 나는 확인하지 못했다. 실액션은 CARE5000 조회 1회 외에 검증되지 않았다.
- 미디어 프롬프트 보완 뒤 재평가를 하지 않았다.
- 완료 문구의 ID 추출은 휴리스틱이다. 하이픈 없는 전화번호를 ID로 볼 수 있고, 글자 없는 하이픈 숫자 ID는 놓친다.
- 턴 예산 때문에 Retry-After 대기를 건너뛰는 경로는 단위 테스트가 없다.
- 고객이 제시한 값과 저장값을 코드에서 대조하는 기능은 없다(모델은 마스킹된 값만 본다).
- 3,000회 상한 카운트는 재시작 시 초기화된다.
- 귀속 확인용 추가 조회(API-07/12)가 채점에 미치는 영향은 모른다.

## 6. 다음에 참고할 사항

- **Gemini 도구 정의:** 중첩 객체와 `additionalProperties`를 피한 평면 형태를 기본으로 둔다. `load_operations(flat=False)`로 원형 비교가 가능하다. `MALFORMED_FUNCTION_CALL`은 `native_finish_reason`으로만 구분되므로 진단 로그에 남긴다.
- **검수와 구현의 분리:** 검수가 SHA로 판을 고정하므로, 수정 뒤에는 해시·테스트 수·미검증 항목을 보고 상단에 갱신한다.
- **실시각 기록:** 시각은 실제 `date` 결과만 쓴다. 이 세션에서 추정 시각을 썼다가 정정한 일이 있었다.
- **경로 문제:** 실행 폴더가 `~/.local/share/ai-top-2026` 스냅샷이므로, 소스 수정이 자동 반영되지 않는다. 반영하려면 root의 운영 절차([`docs/로컬-운영.md`](../로컬-운영.md))를 따른다.
