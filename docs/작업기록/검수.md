# 검수 담당 작업기록

대회: AI TOP 2026 / 작업일: 2026-10-31 / 최종 검수 보고 확정: 14:47:19 KST

## 목적과 기록의 범위

구현 담당과 독립적으로 실제 결함을 재현하고, 수정판의 해결 여부를 확인하는 역할을 맡았다. 코드·원본 자료·지식·설정을 직접 고치는 대신 우선순위, 근거, 위치, 재현 결과와 검수 상태를 보고서에 남겼다. 구현이 병행 변경돼 파일 수정시각과 SHA-256으로 판을 고정했다.

이 기록에서 직접 수행으로 적는 범위는 액션 연동 검수의 S3 이후 재확인, 모의검사, 승인된 실모델 실험, 운영 근거 읽기 및 최종 카카오 UI 시도다. 초기 R1~R8과 앞선 자료별 검수 이력은 대화·인계 기록 및 기존 보고서로 참고했으며, 포크나 인계로 받은 내용을 이번 구간의 새 작업으로 다시 계상하지 않았다. 원문 지식의 후순위 재검수를 전부 완료했다고도 주장하지 않는다.

## 직접 수행한 작업과 주요 판단

### 1. 액션 연동 독립 검수와 수정판 재검수

`bot.py`, `test_bot.py`, README, 공식 OpenAPI 사본과 연결 경로를 읽고, 임시 사본에서 합성 고객·주문과 `httpx.MockTransport`로 경계 사례를 만들었다. 오프라인 검사에서는 환경값을 비우고 socket/DNS를 차단했다. 구현 코드는 수정하지 않았다.

- **인증·TC 격리:** 고객 본문의 계정 줄, 전부 별표인 번호, 같은 TC의 계정 교체, TC 변경 후 이전 history/조회 근거 재사용을 구분했다. 공식 선두 `case metadata`를 대회 합성 컨텍스트로 수용하는 경로는 보존하면서 일반 서비스의 실제 로그인 인증과 동일시하지 않았다.
- **권한·접수:** 고액 환불의 `reason`에 “하자가 아님” 같은 낱말만 있어도 예외를 통과하던 경로를 재현했다. 사유 문자열보다 확인된 상태·조건을 근거로 삼도록 지적했고 수정 후 차단을 확인했다.
- **정보 유입·완료 근거:** 타인 주문을 거절해도 내부 자동 조회 원본이 다음 턴 history에 남는 문제를 찾았다. 마스킹 후에도 배송 상태가 남는 경로까지 재확인했다. 또한 무관한 GET 200, PAID/SUBMITTED, 다른 주문의 CANCELED가 완료 표현을 허용하는 문제를 단계별로 재현했다. 마지막에는 같은 목록의 A=CANCELED/B=PAID를 각각의 레코드로 연결하지 못하는 결함을 찾아 수정판에서 해결을 확인했다.
- **호출·응답 경계:** Retry-After가 후속 호출에도 적용되는지, 남은 턴 예산 때문에 재시도를 중단하는지, 큰 도구 결과가 깨진 JSON으로 잘리는지 확인했다. returned 재배송지 예외는 집하 전·전부 RETURNED 허용, 진행 중/배송완료/혼합/조회 실패 거절을 모의 검증했다.

기존 검사 수가 33→37→40→45→50→51→52개로 늘어나는 동안 별도 경계 재현을 함께 사용했다. “기존 테스트 통과”만으로 실제 결함 해결을 판정하지 않은 이유다. 최종 후보의 기존 모의검사 **52개 통과**, 지정 P1/P2 해결 유지로 판정했다.

### 2. 실모델 오류 진단과 평면 도구 후보 선택

실모델·실카카오 테스트 소유권이 검수로 변경된 뒤, 사용자 승인 범위에서 OpenRouter의 `google/gemini-2.5-flash`만 실제 호출했다. 액션·콜백은 로컬 모의로 고정하고 다른 네트워크 목적지는 차단했다. 키는 인증에만 사용하고 값이나 요청 헤더를 기록하지 않았다.

첫 L03 합성 3턴에서는 최종 주소 전달 뒤 두 응답 모두 HTTP 200이지만 `native_finish_reason=MALFORMED_FUNCTION_CALL`, `tool_calls=[]`, `usage=null`이었다. 두 번째 요청에 복구 system note가 1회 포함됐음을 확인했으나 회복되지 않았고 POST는 0회였다. 반환된 도구명·인자가 없으므로 “API24를 생성하려던 실패”는 맥락상 추정으로 남겼다. 실패 후 같은 에피소드를 추가 반복하지 않았다.

이어서 승인된 A/B 원인 분리 실험을 **14:31에 각 1회** 수행했다. 작업 중 KB가 바뀐 것을 발견해 비교에는 보관된 S9 지식·대화를 고정했고, 두 요청의 messages SHA가 동일함을 확인했다. 원스크립트의 일괄 5회 호출과 비동기 request hook 문제는 검수용 사본에서 단계 실행·비동기 guard로 보완했다.

| 실제 모델 실험 | 관측 결과와 판단 |
|---|---|
| A: 전체 40개 중첩 도구 | 2,340ms, MALFORMED_FUNCTION_CALL, usage 미제공 |
| B: 전체 40개 평면 도구 | 1,614ms, 정상 API24와 정확한 주문번호·전체 새 주소 반환 |

A/B 차이가 명확해 C/D·이름 치환은 실행하지 않았다. B는 평면화와 전송용 `additionalProperties` 제거를 함께 바꾸므로 어느 한 요소가 원인이라고 확정하지 않았다. 선택판은 원래 body 복원·로컬 schema 검증을 유지했다. 승인 코드 SHA는 `e0dce620ce45ed9cb31149bd10c1294f59b5c4257e656ef4c4047e974e43f22a`다.

Y24와 Y07b도 각각 비액션 실모델 1회 점검했다. Y24는 주요 공시값은 맞았으나 정확 상호·공시 페이지 경로·비공개 범위 설명이 빠져 부분 적합이었다. Y07b는 환불 사유를 단정하지 않고 재확인해 한정 목적에 적합했다. **Y07b는 실제 음성이 아닌 합성 전사문 검사**다.

### 3. 운영 읽기 검토와 카카오 테스트 인수

launchd plist·로컬 운영 문서·봇 종료/로그 경로 및 로컬 Apple man을 읽었다. `ThrottleInterval=30`을 종료 후 무조건 30초 대기로 설명하지 않도록 지적했다. 중복 수동 실행, 정상 종료 시 자동 재시작 범위, 로그와 지속 저장 한계를 구분했으며 새 인프라를 요구하지 않았다.

배포·프로세스 조작은 감독이 수행했다. 나는 runtime 코드/media 해시와 KB 255+11건, 비밀 없는 로그 줄을 읽어 확인했다. **14:38:25 READY, 14:39:26 READY는 직접 로그에서 확인**했다. SIGKILL 1회, 자동복구의 인과 및 `running/runs2/PID62940`은 감독이 전달한 실행 증거다. 내가 서버를 배치·종료·재가동한 것이 아니다.

14:13 일반문의 1회는 인터뷰 담당이 발송·수신 기록을 남겼고, 감독이 성공 로그를 전달했다. 나는 79자 수신 원문과 `latency_ms=2185 bubbles=1 chars=79`를 대조해 기록을 인수했다. 직접 재발송하거나 그때의 UI 수신을 새로 관측한 것은 아니다.

최종 상시서비스 질문은 감독의 UI 인계 후 직접 시도했으나 브라우저 연결과 native 입력창 대상 확인에 실패했다. 다른 인물의 창에 보내지 않도록 즉시 중단했고, 재인계 뒤에도 입력창이 메뉴 트리로만 읽혀 다시 중단했다. **검수자 입력·발송 0회**, 현재 상시서비스의 최종 카카오 왕복은 14:47 마감 당시 미검증으로 남겼다. 과거 action OFF 성공을 현재 action ON 성공으로 대체하지 않았다. 이후 사용자 직접 발송 결과는 이 세션에서 확인하지 않았다.

## 미완료·한계와 다음 참고 사항

- 코드 승인은 모의검사와 소수 합성 실모델 표본 범위다. **실제 업무 POST/reset, 실제 주문 처리·접수 성공은 검증하지 않았다.** 실모델 E2E의 POST는 모두 모의다.
- 상세주소 질문이 덜 명확했고, 최종 답에서 접수번호·담당 확인 후 처리 확정 안내가 빠졌다. Y24 잔여, 실제 오디오 인식, 최신 KB 전체의 응답 정합성 및 모든 예외 업무도 완료로 주장하지 않는다. 지연은 소수 표본이며 p95가 아니다.
- 임시 사본을 재사용할 때는 보고서의 코드·지식 해시를 함께 맞춰야 한다. 결과 파일이 있으면 재실행을 거부하는 가드를 두었다. 오류 응답의 usage 미제공을 0토큰으로 바꾸거나, 서로 다른 KB의 결과를 동일 조건 비교로 합치지 말아야 한다.
- 대화·중복 기록·호출 누적의 지속 저장은 미구현이다. 현재 실행 상태를 확인하려면 감독 운영 기록을 기준으로 삼아야 하며, 이 작업기록 작성 중에는 새 검증·API·UI·서버 조작을 하지 않았다.
- **대회 종료 후 사용자가 전달한 최종 상태:** 제출봇 멍멍이 App ID **702917**, LaunchAgent **gui/501/local.ai-top-2026.bot**, 실행 폴더 `/Users/lyuhoyun/.local/share/ai-top-2026`, 모델 `google/gemini-2.5-flash`. 지식 **266건(255+11) 전체 프롬프트**를 사용하며 검색 CLI는 내부용이고 런타임 검색은 미연동이다.
