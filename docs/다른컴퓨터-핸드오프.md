# 다른 컴퓨터 실행 핸드오프

2026-10-31 14:49 KST. 현재 Mac의 상시 봇은 계속 실행 중이다. 이 자료 생성만으로 서버가 이전되지는 않는다.

## 바뀌지 않는 것

컴퓨터를 바꿔도 같은 카카오 Developers 앱·봇을 쓰면 앱 ID, 봇, 채널 링크는 그대로다. 새 앱이나 채널을 만들 필요가 없다. 기존 KAKAO_BOT_TOKEN을 새 컴퓨터에서 사용한다. 현재 구현은 앱 ID를 직접 읽는 환경변수가 없다. 앱/봇 자체를 새로 만들거나 토큰을 재발급하면 별도 변경이다. API 허용 IP 제한을 별도로 설정했다면 새 출발지 IP도 허용해야 한다.

## 포함 / 제외

ZIP은 실행 코드, 고정 의존성, 검수 지식255건+초기11건, 액션 명세, 모의검사, 검색도구와 이 문서를 포함한다. 실제 .env/키·로그·가상환경·대화자료 원본은 제외한다. 검수 지식은 내부 업무 자료이므로 공개 저장소나 공개 링크에 올리지 않는다.

## 1. 연결 전 준비 — 기존 봇은 계속 유지

Mac·Linux·Windows에서 ZIP을 일반 사용자 폴더에 푼다. 자동 서비스가 Documents·Desktop·동기화 폴더 접근에서 막히지 않도록 전용 실행 폴더를 권한다. uv를 공식 안내대로 설치한다: https://docs.astral.sh/uv/getting-started/installation/

해제 폴더의 터미널에서:

```sh
uv sync --locked --python 3.12
uv run --locked python -m unittest discover -p 'test_*.py'
```

현재 패키지의 검사 기준은55개 통과다. 새 OS의 가상환경은 위 명령으로 다시 만들고, 기존 .venv를 복사하지 않는다. Windows PowerShell에서도 위 명령은 같다.

.env.example을 .env로 복사하고 값을 안전한 경로로 옮긴다. Mac/Linux는 `cp .env.example .env`, PowerShell은 `Copy-Item .env.example .env`를 쓴다.

|변수|필요성|
|---|---|
|KAKAO_BOT_TOKEN|필수. 제출 봇의 인증 토큰. REST API 키와 다르다|
|OPENROUTER_API_KEY|필수. 모델 호출 인증|
|AI_TOP_ACTION|업무 액션에 필수. 없으면 액션OFF 안내모드|
|OPENROUTER_MODEL|기본 google/gemini-2.5-flash. 검수 모델 유지|
|KAKAO_REST_API|기존 보관 값. 현재 bot.py는 직접 사용하지 않음|

실제 값은 ZIP에 없다. 현재 Mac의 원본 `.env` 또는 운영 사본 `~/.local/share/ai-top-2026/.env`에서 안전하게 이전한다. 채팅·문서·Git에 값을 붙이지 않는다. Mac/Linux에서는 `chmod 600 .env`로 접근을 제한한다.

카카오톡 앱을 새 서버 컴퓨터에 설치할 필요는 없다. 봇은 카카오 게이트웨이에 나가는 WebSocket 연결을 사용한다. 서버 공개 포트/고정 IP/포트 포워딩은 현재 구조에서 필요하지 않다. 인터넷에서 Kakao gateway(443), Kakao callback, OpenRouter, 대회 액션 서버와 첨부 CDN에 접근할 수 있어야 한다.

## 2. 실제 전환 — 봇은 한 곳에서만 실행

준비·오프라인 검사를 마친 뒤 기존 Mac에서 아래 서비스만 중지한다.

```sh
launchctl bootout "gui/$(id -u)/local.ai-top-2026.bot"
```

새 컴퓨터에서:

```sh
uv run --locked --env-file .env python bot.py
```

Mac에서 수동 실행 중 절전 방지가 필요하면:

```sh
caffeinate -i -s uv run --locked --env-file .env python bot.py
```

로그에 `action api enabled operations=40`과 `gateway READY`가 모두 나와야 한다. 이후 멍멍이 채널(http://pf.kakao.com/_xmaNWX)에 일반 질문1건을 보내 실제 응답과 `reply success` 로그를 확인한다. READY만으로 정상응답이라고 판정하지 않는다. 동일 토큰의 기존/새 봇을 동시에 실행하지 않는다.

## 3. 지속 운영

수동 실행 터미널을 닫으면 서버가 중단될 수 있다. Mac은 launchd, Linux는 systemd, Windows는 작업 스케줄러 등 대상 OS에 맞는 자동 시작·비정상 종료 재시작 설정을 완료하고 재시작 후 왕복까지 확인한다. 현재 Mac의 설정을 그대로 다른 PC에 복사하지 않는다(경로·계정·OS가 다름).

현재 Mac은 전용 실행 폴더 `~/.local/share/ai-top-2026`, 서비스 `local.ai-top-2026.bot`, 로그 `~/.local/share/ai-top-2026/bot-service.log`를 사용한다. launchd READY 및 SIGKILL 후 자동 재연결을 확인했다. 소스 저장소와 운영 사본은 분리되어 있어 수정 반영 때 동기화해야 한다.

현실2026-11-01 24:00 KST(11월2일00:00)까지 전원·인터넷·절전/로그아웃 상태를 관리한다. Mac은 덮개를 열고 전원을 연결한다. 새 OS 자동실행은 이 ZIP에서 검증되지 않았다.

## 4. 실패 시 복구

새 컴퓨터의 봇을 먼저 Ctrl+C로 중지하고 새 자동서비스도 멈춘다. 기존 Mac에서:

```sh
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/local.ai-top-2026.bot.plist"
```

기존 로그의 새 READY와 실제 채팅 응답을 확인한다. 중복 실행·인증 오류(4001/4003/4004)가 나면 토큰 재발급부터 하지 말고 먼저 같은 봇 프로세스가 두 곳에 떠 있는지 확인한다.
