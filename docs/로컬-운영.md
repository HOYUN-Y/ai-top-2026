## 운영 유지

`caffeinate -i -s`가 프로세스 생존 중 유휴 절전을 방지하고 AC 연결 중 시스템 절전을 억제한다. **전원·인터넷 연결, 덮개 열린 상태, 사용자 로그인**을 유지한다. 덮개 닫힘·전원 끊김·인터넷 장애·재부팅 후 로그인 없는 운영은 보장하지 않는다.

launchd는 비정상 종료 시 재시작하며 실행 시작 빈도를30초로 제한한다. 네트워크 단절은 봇 자체 재접속이 담당한다. 인증 오류처럼 코드가 정상 종료하는 상황은 로그를 보고 원인을 고친다. 대화·중복처리 기록은 메모리 기반이므로 재시작 시 초기화된다.

현실 **2026-11-01 24:00 KST(11월2일00:00)**까지 유지한다. 자동 종료는 설정하지 않았다.

## 수정 반영·다른 컴퓨터로 이전

현재는 운영 사본을 실행하므로 **저장소를 수정하는 것만으로 운영에 반영되지 않는다.** 지식은 검수 후 운영 사본의 같은 상대 경로로 복사하면 다음 요청에서 다시 읽는다. 코드는 검수 후 사본을 갱신하고 서비스 재시작이 필요하다. .env 키를 바꿀 때도 운영 사본과 재시작이 필요하며 키를 문서나 메시지로 전달하지 않는다.

다른 컴퓨터에는 Python3.12이상과 uv를 준비하고 소스·pyproject.toml·uv.lock·검수 지식·OpenAPI를 옮겨 `uv sync --locked`로 그 운영체제의 환경을 만든다. 기존 .venv를 다른 OS로 복사하지 않는다. 키는 대상 컴퓨터의 .env에 안전하게 설정한다.

패키지와 설정을 확인한 뒤 기존 봇을 종료하고 새 컴퓨터에서 하나만 실행한다. 동일 토큰으로 동시에 두 봇을 돌리지 않는다. 새 환경에서 gateway READY와 실제 카카오 응답을 확인하고, 실패하면 새 봇을 멈춘 뒤 기존 서비스를 다시 시작한다. 대화 상태는 이전되지 않는다. 자동 실행은 해당 OS에 맞게 설정한다.
