## 검토 기준

각 후속 질문은 발송 전에 수신인·정확한 문구·글자수·목적·기존 자료와 중복 여부를 확인한다. 수신 후에는 답변 원문과 요약, 출처·조건·예외·미확인 사항, 전송 횟수 및 상태 명령 횟수의 일치 여부를 확인한다.

## 발견한 기록 문제와 조치

- 답변 원문 JSON에는 수신 완료인데 관계자 Markdown과 색인은 답변 대기로 남아 있었다. 담당자에게 원문 우선으로 문서 상태를 맞추도록 지시했다.
- 카카오톡 추가 전송 자동 승인 차단이 발생하여 일시 중단했다. 사용자가 상태 확인 및 제한 내 후속 인터뷰를 명시 승인한 뒤 재개 지시했다.
- 후속 일반 질문은 `interviews/NEXT.md`의 초안을 감독이 검토한 후 전송한다. 상태 명령은 별도 집계한다.

## 사용자 지적 및 감독 판단 수정

주문 조회 API 명세 원문 요청은 이민준의 업무 역할과 대화 맥락에 부자연스럽다는 사용자 지적을 받았다. 감독이 해당 질문을 승인한 판단을 수정한다. 실제 이민준 답변도 원문 제공 불가이며 구체적인 상담 범위·이관 상황을 하나씩 물으라고 했다. API가 없다고 결론내리지 않는다. 이미 소모한 질문은 반복하지 않는다.

앞으로는 **그 인물이 실제로 담당하는 고객 상황 → 확인하는 사실/도구 → 처리·판단·이관 순서**를 묻는다. 개발용 명세 요구를 먼저 하지 않는다. 아직 미전송인 홍이장·구방만 질문도 자료 요청보다 업무 상황과 책임·처리 순서가 먼저 나오도록 재검토하며, 종전 발송 승인을 보류했다.

## 비즈니스 상황 질문으로 교체

사용자 지시에 따라 이전 자료 원문 요구 후보를 폐기하고 다음 두 질문을 감독이 직접 문구·한도·중복 검토했다. 고길동/이민준에게서 각 담당 범위만 확인했고, 아래 고객 상황의 실제 확인·책임·연락 순서는 아직 듣지 않았다.

- 홍이장 (56자): 고객이 받은 수산물이 상했다고 하면, 갯마을에서는 무엇을 확인하고 교동마을과 책임을 어떻게 나누나요?

- 구방만 (59자): 고객이 배송 예정일이 지났는데 물건을 못 받았다고 하면, 기사님은 무엇부터 확인하고 누구에게 알려주시나요?

위 두 문구만 각1회 전송 승인. 이전 계약서/배송기록 요구 문구는 보내지 않는다. 이후 질문은 답변 근거를 읽은 후 다시 검토한다.
