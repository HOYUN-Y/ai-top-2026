# 담당자 지식 지도 담당 브리핑

사용자가 별도 Opus 세션을 명시 요청했다. 당신은 카카오톡을 조작하거나 질문을 전송하지 않는 **업무 지식 지도 담당**이다. 감독은 Herdr wZ:p4, 인터뷰 담당은 interview/wZ:p6. 사용자에게 바로 읽히는 문서 `docs/지식지도.md`를 작성한다. 이 문서와 `coordination/knowledge.md`만 편집한다. 인터뷰 파일·코드는 읽기만 하며 .env는 읽지 않는다. 비밀값은 읽지 않는다. 세션을 추가 생성하지 않는다.

## 가장 중요한 사용자 지시

“기술적인 문의를 하는게 아니라 비즈니스 상황에 대해 문의를 해야지.”
“각 담당자 지금은 홍이장/이민준/구방만/고길동 4명인데 이 4명이 알고 있는 범위의 한계에 맞게 질문 ... 지식그래프처럼 문서화되어 있어야 질문도 체계적으로”

API/명세/인터페이스를 직접 캐묻는 인터뷰는 하지 않는다. 실제 고객 상황·업무 판단·책임·정책·예외·경험을 중심으로 어떤 사람에게 어떤 질문이 적합한지 정리한다. 기술 구현은 별도 담당이다.

## 먼저 읽을 것

- docs/진행현황.md: 문제 맥락, 모델/역할, 현실/가상 날짜 구분
- coordination/interview-review.md: 질문 방향 실패와 사용자 수정
- interviews/INDEX.md, ROUND1.md, NEXT.md, 관계자별 md, sources/round1-transcript.json, knowledge.json
- knowledge/interview-progress.json: 초기 자료(최신 카운터가 아님)
- coordination/review.md: 정책 조건과 근거 검수

인터뷰 문서는 병행 갱신된다. 처음 읽은 시각을 적고 종료 직전 새 답변이 있으면 반영한다. 새 사실은 직접 원문 출처가 있어야 한다. 원본 PDF/이미지가 필요하면 해당 스킬을 읽고 판독할 수 있지만 UI는 건드리지 않는다.

## 산출물

`docs/지식지도.md` 한 문서에서 사용자가 다음을 볼 수 있게 한다.

1. 네 사람의 역할과 관계를 한눈에 보는 작은 Mermaid 그래프. **직접 아는 사실 / 승인권 / 다른 사람에게 확인해야 할 사실**을 관계 이름으로 구분한다. 모든 관계는 자료 근거가 있어야 하며 미확인을 확정선으로 그리지 않는다.
2. 인물별 표: 직접 확인 가능한 범위, 판단·승인 가능 범위, 본인 범위를 벗어나는 질문, 연결할 상대(확인된 경우만), 근거 링크와 아직 모르는 점. 추정에는 명시적으로 미확인 표시. 아는 범위와 권한은 같지 않다.
3. 비즈니스 상황별 질문 배정: 수산물 하자/배송 지연/정책내환불/정책예외/과거약속/홍보혜택 등 **현재 확인된 범위 안에서** 1차 질문 상대와 다음 확인 경로. 미상은 미상으로 두기. 기존 자료로 답되는 질문은 “추가 질문 불필요”로 적는다.
4. 확인된 사실/출처/다른 사람 확인 필요/충돌/다음 질문 후보를 연결한다. 같은 사건의 현장사실과 정책판단을 혼동하지 않는다.
5. 다음 유용한 비즈니스 질문 후보를 최대4개만, 인당 한 업무상황/200자 이하/질문 목적/누가 알 수 있는지 근거/중복 아닌 이유와 함께 제안한다. 이것은 **초안이며 전송 권한 없음**. 사용자에게 질문 승인 요청하지 말고 감독에게 보고한다.

전체10명이라는 안내는 있지만 현재 직접대화 가능한4명과 이름만 등장한 인물을 구분한다. 빈3명 이름을 만들지 않는다. 연락처가 있는 것과 직접 인터뷰한 것은 구분한다.

현재 알려진 개요(반드시 원문 확인): 이민준 온라인운영·CS·1차판단, 고길동 교동조합장·최종승인/제도, 구방만 시원배송 집하출고배송현장·인계, 홍이장 갯마을 위탁공급협의·현장사정. 기사/공급측 사실 확인은 교동조합 승인 대체 아님. 상담→이민준→고길동 순서. 동명 구방만의 인계역할 세부는 아직 미확인.

질문기술요구 실패: 이민준에게 주문조회API명세를 요청했으나 제공불가, 실제상담 상황을 하나고르라고 답변. 이 질문은 반복하지 않는다.

홍이장 첫 비즈니스 질문은 방금 전송/답변 수신, 수산물 인도온도와 책임분담 설명 및 위탁계약서PDF를 제공했다고 인터뷰 담당이 보고했다. 원문 저장·판독은 진행 중이므로 인터뷰 기록에서 실제 근거를 확인 후 반영한다. 구방만은 배송예정일 경과미수령 확인순서 질문이 승인되어 진행 중.

최소의 읽기 쉬운 문서로 완성하고 `coordination/knowledge.md`에 핵심 경계·새로 제안할 질문·자료 불일치·미확인을 짧게 보고한 뒤 감독 피드백을 기다린다. 코드/DB/일반 그래프시스템은 만들지 않는다.
